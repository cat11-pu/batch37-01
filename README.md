# GSB Bugfix Task
## 题面
拍卖行和邮件系统是两套老代码，接在一起之后事故不断：成交后物品既不在买家背包也不在卖家背包；买家金币不够也能点领取，东西直接消失；拍卖到期没人出价，货物没有退回；卖家自己给自己抬价把价格顶上去；同一封成交邮件能重复领取，卖家收到两份货款；报价刚好等于起拍价时被判成无效。mail_auction.py 里的 MailAuction 要把上架、竞价、成交邮件、货到付款和过期处理串成闭环。上架时物品从卖家背包取出托管，价格和时长都必须为正；出价不得低于起拍价、必须严格高于当前最高价，金额必须是正整数，超过钱包余额的报价直接拒绝，卖家不能参与自己商品的竞价，截止时刻之后不再收价。到期结算时，有最高价就生成货到付款邮件给买家，没有出价则用退回邮件把物品还给卖家；到期场次按拍卖编号顺序处理。买家领取付款邮件时余额不足要拒绝，邮件保持未付；成功则扣款、物品进背包，并给卖家生成一封货款邮件，卖家领取后钱才真正入账。直接发货到付款走同一套邮件规则，发送者背包里没有该物品不能发，收件人不能是自己。未付款邮件过期后物品退回发送者，再次领取一律拒绝。货款邮件只增加金币，退回邮件只归还物品。整个流程中任何校验失败都不能改变钱包和背包，状态查询返回钱包、背包、拍卖和邮件的独立副本；同一玩家的多封邮件互不影响，领取一封不会动到其他封；所有金额都按整数结算，不产生小数余额。

## 运行方式
```bash
python -m pytest tests -q
```
