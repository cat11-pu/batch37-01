# GSB Bugfix Task
## 题面
制作台改成多人排队后，连续点制作就开始出错：队列满了还继续接单，材料等到开工才扣，两个玩家同时排同一配方会抢同一批铁矿；取消排在后面的单子却把前面单子的材料一起退掉，已经开工的单子取消还能全额返还，跨过完成时间再上线看不到产物，队列里显示的顺序和实际开工顺序相反。不同玩家的队列互不影响，同一玩家连续完成多单时产物按顺序发放，取消后释放的容量可以继续接新单。crafting_queue.py 的 CraftingQueue 需要实现 enqueue、tick、cancel、status 和 state。要求每名玩家的队列有固定容量，入队时校验配方、数量与任务编号并预扣材料，任务按入队先后开工，到点后发放产物并标记完成，status 要按顺序给出任务编号、配方、数量、状态、开始时间和结束时间，只有尚未开工的任务可以取消并全额退料，已开工或已完成的任务取消报错，tick 的时间参数不能倒退；未知配方、材料不足、重复编号和非法数量都抛 ValueError。

## 运行方式
```bash
python -m pytest tests -q
```
