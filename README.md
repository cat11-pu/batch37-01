# GSB Bugfix Task
## 题面
公会副本改成名单制以后，管理层每天在处理同一类工单：副会长把刚入会的小号随手提成官员，谁都能开团；开团不校验名单，路人也能进本输出；同一个 Boss 隔天就重新开，玩家一周领了三次工资；伤害统计在掉线重连时清零，结算按人头平分，主力输出和挂机拿到的一样多；有人先把小号塞进名单蹭结算，打完立刻退会再进，锁定时间跟着清空；首领倒下以后还能继续打，血量被打成负数；奖励算出来带小数，零头没人认领；抽成没有进公会金库，金币凭空消失；同一场结算点了两次，邮件发了两轮；周末连开三场，同一个副本编号被重复使用，战报叠成一团。guild_raid_ledger.py 里 GuildRaidLedger 管名单、职位、开团、伤害台账和奖励分配。名单里每个角色带职位，只有官员和会长能开团，升职只能由会长操作，重复招募同一角色、给不存在的公会招人、越权升职都要拒绝。raid 配置里有归属公会、Boss 血量、奖池和锁定组；开团把状态置为 open 并复制满血；只有本会成员能输出，实际伤害取剩余血量与上报量的较小值，血量归零立刻转成 cleared，清掉之后再打报错。结算要求已击杀且只能结算一次；抽成按奖池的万分比进公会金库，剩余部分按有效伤害占比分配，伤害低于门槛的成员拿零，整除剩下的零头给伤害最高的人，同伤害按角色名升序。锁定按公会、锁定组和角色记录，参战成员结算后进入冷却，冷却期内不能参加同组的新团，未参战成员不受影响。state 返回公会成员与金库、每场团的剩余血量、伤害表和结算明细，且与内部数据完全隔离。

## 运行方式
```bash
python -m pytest tests -q
```
