# GSB Bugfix Task
## 题面
背包和制造台拆成两个服务之后，玩家丢东西的工单翻了三倍：材料明明够，点制造却提示不足；制造扣了材料，成品因为背包满了直接蒸发；两件装备叠在一格里超过上限；拆堆时从最后一格开始扣，前面留着零碎数量；队列里第二件成品比第一件先出来；成品已经放进背包，队列里还挂着未完成；背包满了以后整个制造队列卡死，清出空间也不会恢复。inventory_craft.py 里的 InventoryCraft 要把格子背包、配方材料和串行制造队列连成一体。背包按行列铺开，每格有堆叠上限，格子编号从零开始按行优先排列；放入物品先补已有同类堆，再占用空格，放不下就整笔拒绝，不能只放一半，成功返回该物品的总数；取出从编号最小的格子开始扣，超出持有量拒绝，返回剩余数量。制造前检查配方存在、数量为正、物品名合法、每种材料都够，并且扣完材料后成品也放得下，任何一项不满足都不扣材料、不入队；通过后材料立即扣除，任务按提交顺序排队，等待时间依次累加，不会并行。推进时间时严格按队列头处理，只有队首完成才轮到下一件，后一件即使到期也不能插队；成品放不下时队列停在原地，等背包腾出空间后再次推进才继续。查询数量、格子明细和任务队列都返回独立副本，修改快照不会影响真实库存；同一物品可以占用多个格子，统计时按所有格子求和；制造任务的产出数量按配方乘以提交数量计算，时间也按同样倍率放大；任务完成后对应记录保留在队列历史里，状态标记为已完成。

## 运行方式
```bash
python -m pytest tests -q
```
